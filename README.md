### Backdoor в vsFTPd 2.3.4 (Порт 21/tcp)

        Описание: В код популярного FTP-сервера vsFTPd версии 2.3.4 был намеренно внедрен бэкдор. При подключении с определенной последовательностью символов в имени пользователя злоумышленник может получить оболочку с правами суперпользователя (root).

### Уязвимость удаленного выполнения кода в Java RMI (Порт 1099/tcp)

        Идентификатор уязвимости: Общая проблема конфигурации, часто обозначаемая как CVE-2011-3556 и другими.

        Описание: Службы используют устаревшие и небезопасные параметры шифрования. Обнаружено несколько проблем:

        Идентификаторы уязвимостей: CVE-2015-4000, CVE-2014-3566.


## Задание 2
Чем отличаются эти режимы сканирования с точки зрения сетевого трафика?

Разница между SYN и FIN/Xmas сканированием стала очевидна на практике:

    SYN-сканирование: Отправляет "легальный" SYN, получает в ответ на открытые порты SYN-ACK, затем сам отправляет RST для разрыва. Это выглядит как микросоединение. В вашем выводе это привело к точному определению состояния портов (open).

    FIN/Xmas-сканирование: Отправляет "странные" TCP-пакеты (FIN или гирлянду флагов). В случае с Metasploitable это вызывает одинаковый ответ (RST) на все порты, что не позволяет точно идентифицировать открытые. Сетевой трафик в Wireshark будет состоять из последовательности: [FIN-пакет] -> [RST-пакет] для каждого порта, без вариаций.

2. Как отвечает сервер?

    На SYN-пакет к открытому порту → сервер отвечает SYN-ACK (это позволило nmap точно определить открытые порты).

    На FIN/Xmas-пакет к ЛЮБОМУ порту (открытому или закрытому) -> сервер отвечает TCP RST. Это нестандартное поведение с точки зрения RFC, характерное для многих старых систем. Именно из-за этого ответа nmap не смог отличить открытый порт от закрытого и выставил статус open|filtered
